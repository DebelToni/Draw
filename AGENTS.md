# Draw project contract

- Canonical source on DGX; Mac is used for Xcode builds. Preserve existing app data when installing updates.
- Anton accepts a shipped build as working and reports regressions when encountered. Run automated checks, but do not require a manual iPad checklist or repeatedly leave hardware validation as an open task. Never claim a physical test actually occurred when it did not.
- Keep the 200 ms save debounce for now; rapid strokes may share a history entry. Carry-to-next-page flushes current ink, then duplicates whole strokes/AI objects at or below a chosen Y onto a new page immediately after the source, preserving negative-Y crossing geometry and immutable assets. Never crop source geometry or reveal the hidden upper portion by refitting. G−/G+ controls are removed for now; retained branches remain intact. Undo is iPad-local, per page, with branches retained within two successful-Sync windows. Failed Sync never prunes it. Remote storage and the one-root-commit Draw-data backup retain current heads only; see local-undo.md. When an upgrade would require migrating old undo graphs, reset that history while preserving current combined page states instead; current-state recovery remains required. Snapshot cleanup must compare UUID-relative identities, never absolute paths, and preflight readable retained files plus a complete inventory before deletion.
- Local iPad data plus manual DGX sync is the chosen backup workflow. Reconstructable drawing data also goes to the separate private your-account/Draw-data repository. Include current page PNGs as well as reconstructable current drawing snapshots, so the backup is readable without Apple software. Do not commit live databases, credentials or signed apps there. GitHub is provisional; R2 or other storage can replace it later.
- Note assistance uses Draw-managed interactive `pi --unlisted --fast` workers (OpenAI/Codex priority mode with medium reasoning on launch/resume) in tmux session `Draw-notes`, with one persistent exact Pi ID per document. Use folder/note tmux window names despite unlisted status, close only after 24 hours idle, and resume the same Pi ID after shutdown/rename/move; inherit full normal global Pi tools and shared note-project `AGENTS.md`, and keep answers fast and page-only by default rather than Learn-style questioning. The managed workspace is `notes-workspace/`; V1 behavior and the one-time teal-to-purple migration are specified in ai-assistance.md. The assistance broker is `draw-notes.service`, loopback 18881 and private `/draw-ai`; never use 18876, which is Google CDP. See notes-agents.md and notes_service/README.md for lifecycle, APIs and limitations.
- Maintain server/README.md alongside server/CLI changes as the canonical reference for retrieving documents, pages, spans, tags and current-revision limitations. Agent-facing API provides document/page metadata and cached page PNGs, including spans. No server OCR is used. New explicit-paper scenes and generated assets composite current page content; legacy previews remain ruled. Assistance captures actual native paper/ink layers, with page-content semantics supplied by the reading agent, not fabricated metadata. Renderer/browser isolation applies to assets, not the worker's normal global tools.
- Home folders form an organization tree. Keep document/page/snapshot IDs and drawing directories unchanged; deleting a folder moves its direct documents and child folders to its parent (Home for a root folder), never deleting notes. Folder moves must reject cycles. Empty folders, parent links and membership persist through Sync/private backup and remain visible through the revision-pinned agent API. Nested source uses format 3 so older readers cannot silently flatten it; flat legacy formats/digests stay unchanged. Notes workspaces retain the two-level shared-root layout, using the full logical folder path as their label.
- Orientation is a manual Home setting, not automatic rotation. Existing documents are portrait; new documents inherit the mode and open only in the matching mode. Both retain the 3×3 overview.
- Highlighter, selection and ruler use native PencilKit. Start pen width at index `[1]` (1 pt) and color at dark Ink blue `#0033CC` every launch, while retaining tool restoration and in-session choices. Keep pen/marker thickness independent, make quick eraser always return to Pen, scope native editing gestures to Selection, and retain palm/menu suppression elsewhere. Ruler is transient and must turn off outside drawing pages. Tool changes preserve the existing source/history/image format; see native-tools.md. Renderer replacement waits for battery measurements. Worker defaults are 18-point serif answers; do not shrink body text/formulas below 18 unless explicitly requested. Use more blocks/pages instead. Keep space-efficient placement, allowing one-pixel border gaps when visible/readable. Standing instructions belong in shared system-context AGENTS.md; requests contain current-task data, with routing IDs/hashes managed by the bridge. Existing Pi compaction is sufficient; do not add prompt repetition or a separate compaction framework. Model tools use pinned short handles with hashes/revisions/approval evidence resolved internally. Practice generation has no answers by default and reserves at least one-third page after each exercise; infer stuck intent and give a concrete next step with explanation beside the work, grading the first important error without a full solution unless requested. Agent cyan `#00B8D9` marks use 20%-opacity highlights or opaque circles, without adding a pen-palette entry. Relevant captured handwriting/objects may be moved or removed without a dialog; stale targets skip and edits remain Undoable. Native moves require full-stroke native-capture-v2 tiles, and pure generated-object movement reuses immutable PNGs. Resolving a handwritten question recolors the whole question, including its text/formulas/associated marks, to light Blue `#007AFF`, not just the final symbol; preserve surrounding work and unresolved questions.
